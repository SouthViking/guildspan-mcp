# GuildSpan persistence

GuildSpan uses PostgreSQL as the source of truth for hosted identities,
installations, and authorization. SQLAlchemy 2 provides the asynchronous data
layer, psycopg 3 is the PostgreSQL driver, and Alembic owns schema evolution.

The local `stdio` MCP server does not require a database. `DATABASE_URL` becomes
required when code constructs `Database`, which lets local-only users continue
to run GuildSpan without PostgreSQL.

## Configuration

```env
DATABASE_URL=postgresql://user:password@host:5432/guildspan
GUILDSPAN_DATABASE_ECHO=false
GUILDSPAN_DATABASE_POOL_SIZE=5
GUILDSPAN_DATABASE_MAX_OVERFLOW=10
```

Railway-style `postgres://` and standard `postgresql://` URLs are normalized to
`postgresql+psycopg://` internally. Do not commit credentials or place a real
connection string in `alembic.ini`.

## Schema

- `users` stores the Discord identity used during onboarding.
- `guild_installations` stores the servers where the GuildSpan bot is installed.
- `user_guild_access` is the explicit many-to-many authorization boundary.
- `oauth_state` stores FastMCP OAuth registrations and token state. Values are
  encrypted by the application before PostgreSQL receives them.

Installations and access grants are revoked using timestamps and status fields
instead of destructive deletion. Discord snowflakes are stored as strings so
they remain exact across Python, PostgreSQL, JSON, and JavaScript clients.

The hosted runtime derives OAuth-state encryption and GuildSpan JWT signing from
`GUILDSPAN_AUTH_SECRET`. Keep this secret stable and private. Rotating it
requires current sessions and OAuth state to be re-established.

## Migrations

Apply all migrations:

```bash
DATABASE_URL=postgresql://user:password@host:5432/guildspan \
  .venv/bin/alembic upgrade head
```

Inspect generated SQL without connecting:

```bash
DATABASE_URL=postgresql://user:password@host:5432/guildspan \
  .venv/bin/alembic upgrade head --sql
```

Create a future revision after changing models:

```bash
.venv/bin/alembic revision --autogenerate -m "describe the schema change"
```

Review every autogenerated revision before applying it.

## Transaction usage

Repositories share a caller-owned session. The `Database.session()` context
commits on success and rolls back on any exception:

```python
from guildspan.persistence import Database, UserRepository

database = Database.from_settings(settings)

async with database.session() as session:
    users = UserRepository(session)
    user = await users.upsert(
        discord_user_id="123456789012345678",
        username="guildspan-user",
    )
```

Call `await database.dispose()` during application shutdown.
